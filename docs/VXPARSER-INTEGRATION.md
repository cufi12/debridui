# VxParser integration

This feature branch adds the first DebridUI-facing VxParser integration. It is
still isolated from the production branch and production database.

## Included in this branch

- A loopback-only FastAPI management bridge exposes VxParser's existing settings
  metadata and accepts validated updates to existing settings.
- Authenticated DebridUI settings routes expose those controls to the signed-in
  user; sensitive setting names render as password inputs.
- The IPTV settings page includes a VxParser section and a button to create a
  signed, shareable M3U URL.
- The M3U is generated by VxParser. Its localhost stream URLs are rewritten to
  DebridUI proxy URLs protected by an HMAC token. IPTV players can use the
  resulting URL without a DebridUI browser session.
- The stream proxy only accepts valid signed tokens and forwards requests to
  the loopback VxParser process. Playlist tokens expire after 365 days.

## Administrator access

VXParser management endpoints (including reading settings that may contain
credentials, saving settings, and starting sender refreshes) require an explicit
server-side email allowlist. Configure `VXPARSER_ADMIN_EMAILS` as a comma-separated
list of the exact DebridUI account email addresses allowed to manage the shared
VxParser instance. Matching is case-insensitive. If the variable is unset or
empty, management access is denied to every user; there is no implicit first-user
or owner promotion. This variable must be configured only on the isolated test
service first, then separately reviewed before any production change.

## Runtime requirements

The VxParser process is started by `scripts/run-services.py` inside the Docker
image. A Render service using the Node.js runtime does not start this sidecar.
Therefore the production service must not be switched or deployed until the
Docker runtime has been validated on the isolated test service and explicitly
approved.

The bridge listens only on `127.0.0.1:8080`; it is not exposed as a public
service. The Next.js routes enforce DebridUI authentication for configuration
and playlist-link creation. The public M3U and stream URLs use a signed token
signed with the separate `VXPARSER_TOKEN_SECRET` (minimum 32 characters). Do not
reuse `BETTER_AUTH_SECRET` for IPTV token signing.

## Playlist token lifetime and revocation

Each generated M3U link is signed and expires 365 days after creation. The
expiry is checked for both playlist retrieval and every proxied stream request.
A new link can be generated from the DebridUI settings page at any time.

Immediate revocation is currently global: rotate `VXPARSER_TOKEN_SECRET` to
invalidate every previously issued M3U link. Configure this as a separate,
random secret of at least 32 characters on the service. Rotation also means
users must generate new playlist links. Individual per-link revocation is not
implemented because it requires persistent token records and a database
migration; no such migration is included or applied by this branch.

## Data and persistence

VxParser keeps its own SQLite databases and generated files under its package
directory. Render's ephemeral filesystem can lose that state on restart.
Durable custom lists and settings require persistent storage. This branch does
not connect VxParser to the production PostgreSQL database and does not alter
DebridUI's database schema.
